# Сводка решений всех этапов (для правки CLAUDE.md и отчёта)

Источник модели — design.md (разделы 0–5). Ниже — что В ИТОГЕ реализовано в коде
сверх/вместо документа по отчётам этапов домена, A, B, C и ремонта рецензий.

## Модель и домен
- Схема v19. Блок `{name, caption, days: [{from, mask}], removedAt}`; days пуст — «все
  семь» всегда; до первого отрезка — «все семь». normBlockDays: ведущие WEEK_ALL
  отбрасываются. setBlockDays снимает хвост с from ≥ today.
- Пункт daily-min: `schedule` = СВОЯ маска (переопределение; «как блок» = WEEK_ALL);
  хранится как есть, ∧ с блоком — только при чтении. `groupLog: [{from, group}]` —
  история принадлежности блоку, только у daily-min; [] = item.group на всю жизнь.
  Все места создания daily-min ставят `groupLog: []`.
- Эффективные дни: `effectiveMaskOn = scheduleOn ∧ blockMaskOn(findGroup(groupOn(item,
  day)), day)` для daily-min; привычки — только своя маска; блок ищется по имени,
  включая убранные. dueOn/dueNow/weekMaskDays — по эффективной маске.
- Пороги планки: guard — неделя окна с weekMaskDays = 0 → пункт не готов ни к
  повышению, ни к понижению. ЧИСЛИТЕЛЬ порогов — `planWeekCount` (отметки только в
  днях плана), а не все отметки недели. При m = 7 и данных из UI результат прежний.
  «Три закрытые недели» в разборе остаются «из 7».
- `weekPlan(item, keys)` → {planned, done} по dueOn — для сетки разбора.
- Занятость имени `nameTaken`: store.groups ИЛИ item.group ИЛИ groupLog любого пункта.
  renameGroup/updateGroup/duplicateGroup отказывают; addGroup в осиротевшее имя
  разрешён, но отказывает по zeroDaysIn (у пунктов с этим именем не останется дней).
- updateGroup reasons: empty | missing | removed | taken | nodays | zero | storage.
- removeGroup: блок и ВСЕ живые пункты блока (обе области, все типы) — removedAt =
  сегодня; одна запись, полный откат при отказе.
- restoreGroup: пункты с removedAt === дню ухода блока возвращаются по правилам
  restoreItem (тот же день — отмена, позже — новая запись сразу за прежней).
  Ограничение: пункт, убранный поштучно в тот же день до ухода блока, вернётся с блоком.
- Возврат пункта, у которого своя маска ∧ дни блока пусты, — «как блок» (WEEK_ALL с
  сегодня) и строка «Вернулся с днями блока: свои дни в них не попадали» (у блока —
  «Вернулось/Вернулись с днями блока: {имена} — свои дни в них не попадали»).
  Выбрано вместо отказа: уход обратим всегда (инвариант 12), а у убранного блока нет
  формы, где поправить дни.
- ПРАВИЛО ПРЕЕМНИКА (`laterSegmentOf`): убранная запись, у которой есть живой преемник
  (тот же name/type/area/блок, addedAt строго позже её removedAt), в «Убранных» не
  показывается и повторно не возвращается (restoreItemCore → null). Нового поля нет.
  Ограничение: переименованный преемник прежний отрезок не прячет. Заодно закрыт
  прежний дефект: после возврата позже старая запись снова стояла в «Убранных» и её
  «Вернуть» заводил дубль. У упражнений тот же прежний дефект остаётся (вне объёма).
- duplicateGroup: имя «‹имя› (копия)», «(копия 2)»…; копируются подпись, дни на
  сегодня, живые пункты area min (daily и weekly) со своими масками; привычки и
  параметры — нет; копия ≡ migrate(копия).
- deleteGroup, «Удалить блок», GROUP_DELETE_WHAT, ui.groupDelete, group-del СНЯТЫ:
  блок несёт дни, от которых зависит прошлое, — он убирается.
- parseQuickLines: разделитель — первое « · » (U+00B7 с пробельными по бокам),
  регулярка `/^(.*?)\s+·(?:\s+(.*))?$/` на обрезанной строке; «/» не разделитель.
  addActions: daily-min, «как блок», в конец items[], одна запись, откат.
- Смена типа действия (daily ↔ weekly) — только в день заведения (canChangeType,
  typeChangeRefusal: «по счётчику уже есть записи», «пункт сегодня отмечен»;
  setItemType даёт каноническую форму). Перепроверка при сохранении.
- mergeOwnMask(own, выбор, блок) = (own & ~блок) | (выбор & блок); расписание в форме
  пишется только при касании дней/режима.
- scheduleCore/setSchedule: снимают хвост с from ≥ today (прежде только === today);
  «список опустел — отрезок пишется всегда» (канон у пункта, заведённого сегодня).
- groupJoinRefusal: вход в УБРАННЫЙ блок — отказ «Блок «{имя}» убран — вернуть можно в
  «Убранных»» (edit-save, add-save привычек, «+ Новый блок…»).
- migrate v18→v19: блоки в канон (caption '', days [], removedAt null); groupLog у
  daily-min через normGroupLog (идемпотентна; в шаге v1→v2 пересчитывается после
  DEFAULT_GROUPS); блок, на который ссылается ЖИВОЙ пункт, получает removedAt = null;
  шаг v8→v9 заводит блок в каноне; days{} и reviews[] и отрезки schedule не меняются.
- dataCounts: категории `blockDays` («отрезок дней блока») и `groupLog` («запись о
  блоке»). Ограничения: рукотворный файл с неканоническим (но не битым) журналом или
  ведущим отрезком «все семь» получит «ложную потерю»; битая запись + дописанная
  запись рассогласования гасят друг друга в разности.

## Интерфейс
- «Настройки»: секции Расписание (раскрыта) · Привычки · Упражнения · Данные ·
  Система; «Блоки» и «Пункты» сняты; «Граница дня» и «Зачёт дня» — внизу «Расписания».
- Карточка блока `.bcard` (без боковых полей): шапка — имя, подпись справа, сводка
  дней (ежедневно/будни/выходные/«пн, ср, пт»), ↑↓ среди живых, шеврон свёртки
  (ui.blockFold + перерисовка); тап по шапке — форма блока (имя, подпись, дни +
  пресеты Ежедневно/Будни/Выходные, Дублировать, Убрать вторым тапом с последствием
  под кнопкой); тело — компактные строки действий «имя · подпись» (+ дни, если
  эффективные отличаются от дней блока), стрелки внутри блока; «Добавить действия» —
  quick-форма (textarea), «Добавлено: N» на месте кнопки. Карточка «Без блока» с
  быстрым добавлением. «Убранные» — блоки и пункты (кроме убранных вместе с блоком и
  имеющих преемника). Отдельная форма «Добавить пункт» для минимума и подсказка
  «Одно новое дело за раз» сняты; форма добавления осталась у привычек.
- Форма действия: Название, Подпись, Время, [Тип — только в день заведения], Блок,
  Дни («как блок · {сводка}» / «Свои дни»: чипы вне дней блока disabled,
  «Дни блока: …», «Как блок»), Значение+Единица, [Цель], история планки строкой.
  Отказы: «Не останется ни одного дня: {имена}», «Нужен хотя бы один день недели»;
  ноль из импорта без касания — muted «Сейчас не попадает ни в один день блока».
- «Привычки» (секция): сгруппированы по живым блокам без дней; заголовок «Без блока»
  только если выше есть блоки.
- Черновики: производные состояния форм (FORM_UI: editDays, editNorm, editOwn,
  editType, blockDays, groupPick, groupNew) лежат в черновике по ключу формы;
  успешное сохранение снимает черновик; переименование блока переносит черновики
  (renameDrafts); «Дублировать» снимает снимок набранного перед закрытием формы;
  импорт/чистка/возврат/восстановление из зеркала гасят формы (resetSettingsView).
- Якоря: visibleFlash/goneNoteEl пропускают узлы в [hidden]; якорь внутри свёрнутой
  карточки разворачивает её (только у действий, не у привычек).
- Перетаскивание: блок берётся только за шапку; исключения расширены.
- «Сегодня»: заголовок блока — имя слева, подпись справа (.g-cap, --muted) — на
  «Сегодня» и «Привычках» (функция общая); «На сегодня в расписании ничего нет.»
  при живых, но не сегодняшних действиях; пути «Настройках → Расписание / Привычки».
- Разбор: у действия с 0 < D < 7 — «запланировано D дней» (aria-hidden) и sr «отмечено
  n из D» (n — отметки в днях плана); D = 0 — sr «не запланировано»; круги сетки
  выровнены по первой строке имени.
- «Система»: «Всё правится.» — «…убираются в Настройках → Расписание; убранный блок
  уводит из виду свои действия и привычки, отметки остаются.»; к «Блок — связка
  пунктов.» — фраза о днях блока.
- Цепь дней: день без запланированных действий — `.cdays i.off` (29/B), не менялось.
- Снимок разметки форм: 11 форм (edit-min «как блок», edit-min-own, edit-min-new,
  edit-habit, edit-param, add-habit, quick, group-edit, group-add, ex-edit, ex-add).
- Новые/изменённые классы CSS: .bcard .bhead .bline .bcap .bbody .csub .g-cap .g-plan
  .dnow .presets .fold, .g-label flex; новых токенов/кеглей/анимаций нет.
